## 1. 已确认的方向

- **继续 Next.js + React，不进行整站 Vue/Nuxt 回迁。** Hono API 继续保留。适配器或运行时如需调整，另行基于兼容性、性能和成本证据决策，不与前端重写捆绑。
- 新功能默认写在现有 React 主线；保留旧 Vue 代码及被引用样式作为兼容资产。先查引用和补视觉回归，再逐块退出旧资产，不直接删除目录。
- 优先级为：记录可靠性 → 错误可见性 → 可重复验证 → 主流程体验 → 性能 → 新功能。
- 保留“收藏盒”、10 颗独立评分星、在追状态进度操作、评分分布和可读卡片尺寸。
- 现有证据支持“工程契约与质量门禁不完整”，不足以认定“架构漏洞百出”。产品缺陷、技术债和可利用的安全漏洞必须分开描述。

## 2. 本批落地内容

### 2.1 数据契约与错误边界

- `lib/api.ts` 对非法 JSON、空响应、数组和不合约定的成功响应报错，不再假装读取成功；保留 HTTP 状态、超时和私有请求不缓存规则。
- **兼容旧写接口**：评论写入的 `{success:true}` 和收藏删除的 `{message:'已删除'}` 仅作为非 GET/HEAD 写入确认接受。读取页面不能用这种响应冒充资料。
- `components/auth-provider.tsx` 中通用 request 接入同一传输层；保留原有令牌选择和 401 刷新逻辑，不宣称所有认证分支均已重构。
- 新增 `lib/page-data.ts`：必需资料只有真实 404 才进入不存在页面；上游故障进入错误边界；数字 ID 要求正安全整数。
- 人物、角色、话题和小组主资料接入明确的失败处理；部分吐槽、讨论和关联列表区分“没有内容”与“没读到内容”。
- 新增 `components/data-unavailable.tsx`，提供失败提示和刷新重试。详情角色/人员/关联、小组列表初始失败不再静默显示为空。

### 2.2 收藏与异步状态

- 收藏读取中不显示可提交的默认表单；读取失败锁定编辑并支持重试，防止覆盖未知的旧评分和短评。
- 按条目及账号身份隔离编辑器状态，避免切换后沿用上一条目的表单。
- 收藏状态、详情和进度写入共享忙碌锁，减少并发写入互相覆盖；未收藏先选择状态，再保存详情。
- 已知收藏状态传给内层按钮，避免编辑器重复 GET。
- 首页和在追页补充稳定 effect 依赖与过期响应保护；退出登录清理相关弹层。

### 2.3 体验与可访问性

- 详情角色/制作人员列表可以展开全部与收起，不再固定截断在 32 项。
- 首页章节弹层改为原生 dialog，接入标题、Escape 关闭、卸载关闭与焦点恢复逻辑；保留关闭按钮。
- 行为差异：该弹层目前不再通过点击遮罩关闭，后续浏览器验收时评估是否恢复。
- 移除账号页无实际目标的 `href="#"` 导航；整理收藏按钮与评分组语义。
- 以上是实现和自动测试层面的改进；尚未完成多宽度、读屏与真实键盘焦点验收。

### 2.4 防止再次退化的质量门禁

- 新增 React、Hooks、JSX 可访问性 ESLint，零错误、零警告；保留旧 JS/Vue 检查。
- `npm run lint` 串联旧代码 lint、React lint 和业务类型检查。
- `npm run check` 串联 lint、全量测试、Next 生产构建；不包含安装、Worker 打包或部署。
- lint-staged 覆盖 TS/TSX；CI 与 release 缓存纳入三份锁文件，原有 lint 阶段自动采用新门禁。
- 本批延续前一批搜索、分页、时长单位、写请求不重放和 AI 上下文隐私修复，不回退那些改动。

## 3. 工具链隔离：原因、代价和退出条件

本地业务 TypeScript 为 7.0.2。当前安装的 `@typescript-eslint/parser@8.69.0` 声明的 TypeScript peer 范围为 `>=4.8.4 <6.1.0`，直接混装产生兼容冲突。

处理方式：

1. 业务类型检查继续使用根目录 TS7，不降级业务编译器。
2. 在 `tooling/eslint` 建立独立 package/lock，使用 TS6.0.3 供语法解析器使用。
3. 使用 `npm ci --prefix tooling/eslint --ignore-scripts --install-strategy=nested`，避免解析器依赖误用根目录 TS7。
4. 根 postinstall 顺序安装旧客户端和隔离工具链；配置按工具链目录解析 parser。
5. 不使用 `--force`、`--legacy-peer-deps` 掩盖 peer 冲突。

代价是增加一个锁文件和安装步骤；这不是永久架构设计。解析器正式兼容业务 TS 版本后，应在同一变更中合并工具链并验证干净安装。详见 `tooling/eslint/README.md`。

本轮根锁文件主要增长来自 React/a11y lint 插件；两个既有浏览器数据包随安装更新：baseline-browser-mapping 2.11.14 → 2.11.21、caniuse-lite 1.0.30001809 → 1.0.30001810。未借机升级 React/Next 运行时。

## 5. 对过去做法的纠偏

| 代码/流程中体现的问题        | 本轮处理                           | 后续约束                                       |
| ---------------------------- | ---------------------------------- | ---------------------------------------------- |
| 把异常吞成空数组或 404       | 为核心页面和部分列表拆分失败状态   | 每个读取流程须定义 loading/empty/error/success |
| 未读完旧收藏就允许写默认值   | 读取门禁和写入锁                   | 写入前确认原状态；失败不能静默当成功           |

| 迁移后旧样式与新组件耦合     | 暂存兼容资产，不冒险清空           | 按组件逐块替换，每块有桌面/窄屏回归            |
| UI 大量聚集在大型客户端组件  | 本批先抽取错误提示、数据辅助和弹层 | 后续按功能拆分，不先做无收益的批量改名         |
| 工具安装冲突容易诱发强制安装 | 以独立锁文件明确隔离               | 版本升级须有兼容依据和退出方案                 |

这些是实现和流程判断，不归因于某位开发者，也不以某框架天然优劣解释所有问题。

## 7. next-env.d.ts 的白话说明

它是 Next 为 TypeScript 自动生成的“类型索引”，不是业务逻辑，也不是保存密码的环境变量文件。开发和构建时类型产物目录可能不同，导致文件中的引用路径自动变化。**这种变化本身不表示架构坏了。**

本轮核对该文件没有 Git 差异，也未手改它。开发者应修改业务源码/配置，而不是靠编辑这个生成文件解决业务错误。
