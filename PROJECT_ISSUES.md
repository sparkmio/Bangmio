# Bangmio 项目问题总结与分析

> 基于对项目代码、配置、架构的全面审查，按严重程度分类整理。
> 审查范围：前端（client/）、后端（server/）、部署层（functions/、wrangler.toml）、外部依赖。

---

## 一、严重（P0）— 影响核心功能可用性

### 1.1 豆瓣嵌入受反爬限制，无法完整展示

| 项目         | 内容                                                                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **表现**     | 豆瓣 Tab 中 iframe 嵌入豆瓣页面时，服务端代理返回降级 HTML（约 783B），提示"豆瓣页面暂无法嵌入"；随后前端触发 fallback 展示结构化摘要，但摘要内容有限 |
| **影响范围** | 所有用户的豆瓣 Tab                                                                                                                                    |
| **严重程度** | P0 — 特色功能不可用                                                                                                                                   |
| **可能原因** | 豆瓣对 Cloudflare 边缘节点 IP 有 WAF/反爬策略，即使增强请求头（UA、Referer、Cookie）也无法绕过；豆瓣无公开 API                                        |
| **当前缓解** | 服务端返回降级 HTML + 前端 ExternalEmbedFallback 展示 `/summary` 结构化摘要（评分、简介、原站链接）                                                   |
| **建议**     | 接受降级方案作为长期策略；或考虑使用第三方豆瓣数据源（如 DoubanMovieAPI）；或在客户端引导用户直接跳转豆瓣                                             |

### 1.2 Bangumi 上游 WAF 拦截导致小组功能不稳定

| 项目         | 内容                                                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **表现**     | 小组列表/详情在 Cloudflare 边缘节点抓取 Bangumi 页面时，bgm.tv 和 bangumi.lol 可能返回 403/412，导致数据为空或仅展示兜底数据                       |
| **影响范围** | 所有用户的小组功能                                                                                                                                 |
| **严重程度** | P0 — 核心功能不稳定                                                                                                                                |
| **可能原因** | Bangumi 对 CF 边缘 IP 有 WAF 策略；HTML 正则解析对 DOM 结构变化脆弱                                                                                |
| **当前缓解** | 多源重试（bgm.tv → bangumi.lol → bangumi.one）+ 8 个兜底小组 + `degraded` 标识 + 5 分钟缓存                                                        |
| **建议**     | ① 使用 Bangumi 官方 API（如有小组相关接口）替代网页抓取；② 正则解析改为 linkedom DOM 解析，提高鲁棒性；③ 增加用户侧"在 Bangumi 原站查看"入口优先级 |

### 1.3 Bilibili API 从 CF 边缘节点被拦截

| 项目         | 内容                                                                                                                                    |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| **表现**     | 番剧详情页"B站评分"和"在线观看"Tab 中，B站评分数据无法获取（返回 412）                                                                  |
| **影响范围** | 所有用户的评分 Tab 与在线观看 Tab                                                                                                       |
| **严重程度** | P0 — 评分功能缺失                                                                                                                       |
| **可能原因** | Bilibili API 对 Cloudflare 边缘节点 IP 有 WAF 拦截（返回 412 Precondition Failed）                                                      |
| **当前缓解** | 在线观看 Tab 降级为搜索链接（B站搜索 + girigirilove）                                                                                   |
| **建议**     | ① 放弃服务端代理 B站 API，改为前端直接调用（可能受 CORS 限制）；② 或使用第三方 B站数据代理；③ 评分 Tab 中 B站部分明确标注"数据暂不可用" |

## 七、安全问题

### 7.1 JWT 过期后 Bangumi 直登用户无 refresh 机制

| 项目         | 内容                                                                                                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **表现**     | [api/index.js](file:///d:/Bangmio%20v4/client/src/api/index.js) 响应拦截器中，Bangmio 用户 401 时刷新 JWT，但 Bangumi 直登用户 401 时直接清除 token 跳登录，无 refresh |
| **影响范围** | Bangumi 直登用户                                                                                                                                                       |
| **严重程度** | P2 — Bangumi token 不过期（长期有效），实际影响小                                                                                                                      |
| **建议**     | 现状可接受；如需改进可提示"Token 已失效"而非直接跳登录                                                                                                                 |

### 7.2 `X-Bangumi-Username` 头可被伪造

| 项目         | 内容                                                                                                                                                                                                                                            |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **表现**     | [api/index.js#L89](file:///d:/Bangmio%20v4/client/src/api/index.js#L89) 中 Bangumi 直登用户通过 `X-Bangumi-Username` 头传递用户名，后端 [collection.js](file:///d:/Bangmio%20v4/server/src/routes/collection.js) 直接使用该头查询收藏，可被伪造 |
| **影响范围** | 收藏数据                                                                                                                                                                                                                                        |
| **严重程度** | P2 — 仅 Bangumi 直登用户，token 本身不可伪造                                                                                                                                                                                                    |
| **可能原因** | Bangumi 直登用户无 Bangmio JWT，后端无法验证 username 与 token 的绑定关系                                                                                                                                                                       |
| **建议**     | 后端在处理 Bangumi 直登请求时，用 token 调用 Bangumi API 验证 username 一致性（增加延迟），或接受现状风险                                                                                                                                       |

### 7.3 速率限制基于内存 Map，CF Workers 实例间不共享

| 项目         | 内容                                                                                                                                           |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **表现**     | [rateLimit.js](file:///d:/Bangmio%20v4/server/src/utils/rateLimit.js) 的计数器存储在内存 Map 中，CF Workers 多实例间不共享，实际限流效果被稀释 |
| **影响范围** | 暴力破解防护                                                                                                                                   |
| **严重程度** | P2                                                                                                                                             |
| **建议**     | 使用 Cloudflare KV 或 D1 做分布式速率限制（增加延迟与复杂度）                                                                                  |
