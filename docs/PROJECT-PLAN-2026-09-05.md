## 一、执行结论

1. **暂不换回 Vue。** 本轮明确问题主要属于数据契约、状态管理、错误处理、测试缺口和发布流程，不是 React 天生无法解决的问题。现在重写会再承担认证、收藏、评分、社区和视觉回归成本。
2. 保留现有 Next.js + Hono 运行主线，先完成一次可重复发布和两轮用户验收；旧 Vue 只作为功能/设计参考及评估资产，不继续无限期双线加功能。
3. **也不把 OpenNext 永久不变当作前提。** 2026-09-05 实际读取的 Cloudflare 官方页面（标注更新于 2026-08-25）已推荐 vinext 作为默认 Next.js 路径，同时标明 beta，并要求已有生产项目先检查兼容性。把适配器评估与“React 换 Vue”拆开，先验证再迁移，不能把新推荐直接等同于本项目应该立即切换。
4. 产品优先级：**可靠记录 → 快速找番 → 清晰资料 → 轻量社区 → 可控 AI**。没有可观测性和回滚能力时，不增加新的付费/抓取/同步依赖。
5. 以下路线按一个人维护估算，人日不是日历承诺；按每周 2–3 个有效开发日执行，给回归和学习留出约 30% 余量。

### 5.4 预编译样式作为长期源码

复制现有 CSS 能快速恢复视觉，作为过渡合理；长期把它当构建源，新增类可能无效、组件命名与运行时不一致，维护者难判断该改哪里。解决顺序是设计 token → 源码 CSS/组件约束 → 删除无用样式，而非再选一个 UI 套件重写全部页面。

### 5.5 功能数量优先于可用性

第三方评分、百科、播放入口、音乐、AI 各自增加失败面。原则应改为“主信息可靠、扩展可降级”；功能验收包括没有数据、加载失败、未登录、超时和移动端，而非只看成功截图。

## 六、是否换回 Vue：决策记录 ADR-001

### 6.1 必须保留的能力

收藏盒名称、五状态、10 个独立评分选项、评分分布、状态 3 下的进度管理、公共条目可访问、现有 OAuth/账号与 API 契约、国内访问降级、稳定路由和可读卡片。任何候选架构都按同一清单验收。

### 6.2 候选比较（针对本项目，不是通用跑分）

| 方案                                       | 近期收益                                           | 成本/风险                                                                    | 何时选择                                                                 |
| ------------------------------------------ | -------------------------------------------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| A. 保留 Next/React，修好现有工程           | 最大化复用当前路由/认证/组件；立即交付修复         | 仍需处理缓存、适配器、CSS债务；不能假设 SSR 自动变快                         | **当前默认**，先稳定两轮发布                                             |
| B. Vue 3 + Vite SPA + Hono                 | 若维护者更熟 Vue，交互开发和静态前端部署可能更简单 | 旧 Vue 不一定功能对等；公共首屏/分享/索引策略要重做；全部 React UI 迁移      | 以登录后的个人管理为主，且对公共 SSR 没有刚性需求，实测证明维护成本下降  |
| C. Vue SSR/混合渲染（例如 Nuxt）+ Hono     | Vue 体验与公共页面服务端输出可以兼得               | 新框架/适配器/缓存的验证成本仍在；不是去掉复杂度，只是改变来源               | Vue 原型实测胜出且公共资料 SSR 确有收益；Nuxt 具体平台兼容版本需另行核实 |
| D. 保留 React/Next API，评估 vinext 适配器 | 不整体重写组件，可能改善 Workers 工具链一致性      | 官方当前标注 beta；与本仓库 16.3.1、错误边界、缓存、D1、OAuth 的兼容性未验证 | 兼容检查及隔离预览通过后再作单独 ADR，不与 UI 重构同批上线               |

Vue 官方 SSR 指南说明 SSR 可改善首屏内容与索引，但伴随开发约束、构建部署复杂度和服务端负担；先判断需求。**Vue 可以 SSR，Next 可以客户端渲染；框架名不能替代渲染策略选择。**

### 6.3 客观切换门槛

先收集 2 周现有维护数据，再允许一个 **3–5 人日、仅实现搜索→详情→收藏盒的隔离原型**：

1. 固定 API、相同图像/字体、相同设备网络、相同功能断言，比较首屏、交互延迟、JS/CSS大小和构建时间。
2. 至少修同一组 3 个问题，记录真实开发/定位耗时；不同熟练度作为变量记录。
3. 登录回调、收藏回读、缓存隔离、错误与移动交互全部通过，不依靠截图替代行为。
4. 建议只有在关键维护耗时降低约 30%、没有关键能力退化、迁移预计不超过 15–25 人日且收益能在 3–6 个月回收时，才进入正式重构。阈值是本项目的决策预算，不是行业标准或已测数据。
5. 无明显收益、关键依赖不兼容或超过原型预算，立即停止试验；保留当前主线，不为原型投入辩护。

旧 Vue 目录不是可直接回滚的生产版本。回滚应使用实际验收过的 Worker 版本和兼容数据库方案，而不是盲目部署旧 client/dist。

## 七、未来产品方向和体验优化

### 7.1 主方向：轻量追番/阅读记录工具

- 首页优先展示“继续上次进度”“本周更新”“最近记录”，而不是堆满各类榜单。
- 统一书/音/游/动画文案，区分作品收藏状态、累计进度与单集状态；批量改动先预览、成功后可撤销。
- 进度保存展示保存中/成功/失败/最后同步时间。超时后先回读，不自动重复写入。
- 收藏页支持组合筛选、排序和清空条件；数量、分页、当前筛选在同一视图可理解。

### 7.2 搜索和发现

- 输入稿与已执行查询分离，保留 URL；筛选 chips 可单独移除，返回列表保留滚动位置。
- 搜索建议、错字/别名、无结果引导优先于复杂推荐算法。
- 榜单标明类型、口径和时间：热度、评分、当季、全站不混用；避免承诺接口未提供的实时性。
- 首屏先出核心字段；豆瓣/百科/音乐失败不阻断标题、简介和收藏。

### 7.3 移动端、可访问性与稳定视觉

- 建 320/390/768/1440 宽度截图基线；触屏主要操作目标建议不少于 44px，图标有名称、焦点可见。
- 10 星控件保持分离；键盘方向键和选中播报一致；弹窗支持 Escape、焦点返回和背景滚动锁定。
- 图片保留尺寸占位、失败后占位，长标题折行，空白不因图像加载跳动。
- 深浅主题保持文字与背景对比；动效遵循减少动态效果偏好。
- AI 面板和底部导航不遮挡提交按钮，软键盘打开后仍能关闭面板与发送。

### 7.4 社区与第三方信息

- 先保证读帖、来源跳转、分页、失败重试；发帖/回复必须独立授权测试。
- 第三方来源注明来源和更新时间；提供原站回退入口，不声称聚合数据百分之百准确。
- 播放入口优先正规公开来源；不绕过访问控制、不托管未授权视频。不在没有验证访问许可和使用条款时扩展抓取规模。

### 7.5 AI：资料助手而不是默认主入口

- 默认只发用户问题；附加资料需明确同意和可预览，后续改为结构化公开字段而非扫描整页。
- 加取消、超时、失败保留输入、删除本地历史；提示答案可能有误并显示资料来源。
- 用户级/日级额度、token 上限、服务端费用熔断；建议先由负责人设一个可承受的月上限，而不是假设调用单价。
- 未证明用户持续使用前，不增加向量库、多代理推荐或自动后台生成任务。

### 8.1 质量门禁

- PR：锁文件安装、JS/Vue lint、TS typecheck、React规则（待加）、服务契约测试、React组件测试、普通构建。
- 发布候选：完整 OpenNext/未来候选适配器构建、预览 Worker、D1 测试绑定、核心 E2E；不把 next build 当 Worker 运行通过。
- 每次修 bug 先能构造失败用例，再修复，再证明测试从红变绿；截图同时记录加载和失败状态。
- 每次新增第三方请求要有超时、大小边界、失败兜底和来源说明；写入操作不盲目重试。
- CI 输出明确生产产物，上传前扫环境文件/缓存；客户端不得包含服务端密钥。构建产物中的公开 site key 与私密 secret 区分对待。

### 8.2 可观测性与指标（目标，不是当前测量结果）

- 错误按客户端、本站 API、上游来源分层；记录 request ID、状态码、耗时、版本，不记录 token/评论正文/完整 AI 对话。
- 核心任务成功率建议目标 ≥99%；通过小样本先建立基线，分开计算上游故障和本站故障。
- 以真实移动设备 p75 跟踪 LCP/INP/CLS，初期工程目标 2.5s/200ms/0.1；慢网与国内访问单独分组，不能以本机开发模式跑分冒充线上数据。
- 记录首屏 API 次数、客户端 JS/CSS、构建时间、每周修复耗时；禁止无解释地比上一版劣化超过 10%。
- 新用户记录首次收藏耗时、7日回访及核心任务完成率；无追踪授权时仅使用匿名汇总、人工访谈或本地试验，不默认接入侵入式分析。

### 8.3 发布和回滚步骤

1. 负责人审批本地变更、真实测试账号写入范围、commit/push/dry-run/deploy 各动作。
2. 保存当前生产 Worker 版本标识；确认数据库 schema 向后兼容，必要时使用受控备份。
3. 隔离预览环境跑登录、收藏、进度、搜索、详情、错误、AI 默认零请求；确定资源和密钥来自正确环境。
4. 部署后重复同一短验收清单，记录版本、时间、域名、API失败率。
5. 认证无法完成、记录无法回读、跨账号状态异常、主要页面失败任一出现，停止新功能并回滚已知正常 Worker；数据库不做破坏性回滚。
6. 至少观察一个完整使用周期后归档本次发布，更新 README/skill 中确已改变的长期契约。

## 九、明确不做什么

- 不在本轮切 Vue、Nuxt 或 vinext；不升级整套依赖追新。
- 不删除旧 Vue、legacy bundle、用户改动或历史记录来“让工作树干净”。
- 不把编译通过等同于线上账号功能验收，不把生产只读浏览等同于写入测试。
- 不自动提交、推送、部署、轮换密钥、注册账号、写短评或调用计费 AI。
- 不给未经验证的“换框架必然变快”“现在可以直接回滚旧 Vue”承诺。
