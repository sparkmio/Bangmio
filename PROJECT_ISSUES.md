> 基于对项目代码、配置、架构的全面审查，按严重程度分类整理。

## 一、严重（P0）— 影响核心功能可用性

### 1.1 豆瓣嵌入受反爬限制，无法完整展示 ⚠️ 已大幅改善（2026-08-14）

| 项目         | 内容                                                                                                                                                                                                                                                                                        |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **表现**     | ~~豆瓣 Tab 中 iframe 嵌入豆瓣页面时，服务端代理返回降级 HTML（约 783B），提示"豆瓣页面暂无法嵌入"~~ → 已改善：降级页升级为结构化富内容卡片（评分/星级/年份地区/导演主演/热门短评/原站链接）                                                                                                 |
| **影响范围** | 所有用户的豆瓣 Tab                                                                                                                                                                                                                                                                          |
| **严重程度** | ~~P0 — 特色功能不可用~~ → 降级体验已可用（条目页 HTML 抓取仍被反爬拦截，但 JSON 接口全部可用）                                                                                                                                                                                              |
| **可能原因** | 豆瓣条目页对非浏览器环境（含 CF 边缘、本地服务器）有反爬拦截：拦截页/验证页/登录页（实测 cookie 预热无效）；但 `/j/subject_suggest`、`/j/subject_abstract`、`/j/search_suggest` 等 JSON 接口可用                                                                                            |
| **当前缓解** | ① `/page/:id` 抓取失败时用 subject_abstract 数据渲染富内容降级 HTML（iframe 直接展示，不再是一句提示）；② 判定改为正向匹配条目页核心区块（#info/#interest_sectl），杜绝登录页/拦截页混入；③ 搜索升级为 search_suggest（自带评分）→ subject_suggest 双源；④ 前端未匹配时提供豆瓣搜索直达入口 |
| **建议**     | 接受「JSON 数据 + 富卡片」作为长期策略；条目页 iframe 完整嵌入已放弃（上游反爬不可持续对抗）                                                                                                                                                                                                |

### 1.2 Bangumi 上游 WAF 拦截导致小组功能不稳定

| 项目         | 内容                                                                                                                                               |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **表现**     | 小组列表/详情在 Cloudflare 边缘节点抓取 Bangumi 页面时，bgm.tv 和 bangumi.lol 可能返回 403/412，导致数据为空或仅展示兜底数据                       |
| **影响范围** | 所有用户的小组功能                                                                                                                                 |
| **严重程度** | P0 — 核心功能不稳定                                                                                                                                |
| **可能原因** | Bangumi 对 CF 边缘 IP 有 WAF 策略；HTML 正则解析对 DOM 结构变化脆弱                                                                                |
| **当前缓解** | 多源重试（bgm.tv → bangumi.lol → bangumi.one）+ 8 个兜底小组 + `degraded` 标识 + 5 分钟缓存                                                        |
| **建议**     | ① 使用 Bangumi 官方 API（如有小组相关接口）替代网页抓取；② 正则解析改为 linkedom DOM 解析，提高鲁棒性；③ 增加用户侧"在 Bangumi 原站查看"入口优先级 |
